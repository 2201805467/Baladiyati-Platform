# منصة بلديتي | Baladiyati Platform

منصة رقمية للخدمات البلدية في ليبيا، تربط المواطنين بالبلدية وتتيح الإبلاغ عن المشكلات الخدمية، مثل أعطال الإنارة والحفر وتراكم النفايات، ومتابعة معالجتها بالصور والموقع الجغرافي. تشمل المنصة تطبيق هاتف، ولوحات تحكم للموظفين والإدارة، وخادمًا مشتركًا يقدم واجهات REST API.

## أهداف المشروع

- تسهيل تقديم البلاغات ومتابعتها دون الحاجة إلى مراجعة البلدية حضوريًا.
- تنظيم استقبال البلاغات وإحالتها إلى الأقسام المختصة وتوثيق معالجتها.
- تعزيز الشفافية من خلال سجل تقدم البلاغات وتقييم الخدمة بعد الإنجاز.
- تحسين أداء البلدية عبر الإحصاءات والخرائط ومتابعة مهل المعالجة (SLA).
- تشجيع المشاركة المجتمعية بالمقترحات واستطلاعات الرأي والمبادرات التطوعية.
- إتاحة المعلومات البلدية والتنبيهات وقنوات التواصل مع المواطنين.

## مكونات المشروع

```text
Baladiyati-Platform/
├── municipality_system/    # خادم Laravel وواجهات API وقاعدة البيانات
├── baladity-Dashborads/    # لوحات التحكم باستخدام React وTypeScript
├── baladity-mobileAPP/     # تطبيق Flutter للمواطن وموظف القسم
├── presentation/          # ملفات العرض التقديمي
└── README.md
```

يتصل تطبيق الهاتف ولوحات التحكم بخادم Laravel نفسه. يتحقق الخادم من هوية المستخدم ودوره وصلاحياته قبل تنفيذ العمليات، ويحفظ البيانات والعلاقات من خلال Eloquent ORM.

## المستخدمون والصلاحيات

| الدور | المسؤوليات الرئيسية |
|---|---|
| المواطن `citizen` | إرسال البلاغات والمقترحات ومتابعتها، التصويت، والمشاركة في الخدمات المجتمعية |
| موظف الاستقبال `reception` | مراجعة البلاغات وإحالتها أو رفضها، مراجعة المقترحات، والرد على استفسارات المواطنين |
| موظف القسم `department` | معالجة بلاغات القسم، توثيق التنفيذ الميداني، والرد على المحادثات المحالة إليه |
| مدير النظام `admin` | إدارة الحسابات والأقسام والتصنيفات والصلاحيات والمحتوى، ومتابعة الأداء والسجلات الأمنية |

ترتبط الصلاحيات بالأدوار، وتُفحص في الخادم إضافة إلى حماية صفحات الواجهات.

## الوظائف الرئيسية

### البلاغات والعمل الميداني

- إنشاء بلاغ بوصف وصور وإحداثيات جغرافية.
- اختيار التصنيف يدويًا أو الاستعانة بتحليل الصورة لاقتراح التصنيف والوصف.
- البحث عن البلاغات المشابهة وإتاحة الانضمام إلى بلاغ قائم.
- مراجعة البلاغ وإحالته إلى القسم المختص أو رفضه مع بيان السبب.
- متابعة الحالة والتعليقات والمرفقات وسجل الإجراءات.
- تسجيل بدء العمل الميداني وانتهائه وموقعه ومدته، وإرفاق تقرير الإنجاز.
- عرض بلاغات المجتمع والتفاعل معها بالتعليقات والتصويت.
- تقييم معالجة البلاغ بعد إغلاقه.
- متابعة مهلة المعالجة والتنبيه عند قرب انتهائها أو تجاوزها.

دورة العمل الأساسية:

```
إرسال البلاغ ← مراجعة الاستقبال ← الإحالة للقسم ← التنفيذ والتوثيق ← الإغلاق والتقييم
```

### المشاركة والخدمات المجتمعية

- تقديم المقترحات ومراجعتها والتصويت عليها ومتابعة تنفيذ المقبول منها.
- نشر المبادرات التطوعية والتسجيل فيها وتأكيد الحضور باستخدام الموقع.
- إرسال تنبيهات تستهدف المواطنين ضمن نطاق جغرافي.
- نشر المفقودات والموجودات، مع التعليقات والمحادثات الخاصة والإبلاغ عن الإساءة.
- نشر استطلاعات الرأي والتصويت وعرض النتائج.
- التواصل مع البلدية عبر محادثة قابلة للتحويل إلى القسم المختص.
- عرض المشاريع البلدية والمرافق العامة وأرقام الطوارئ.

### الحسابات والإدارة

- تسجيل الحسابات وتأكيدها عبر OTP، واستعادة كلمة المرور وتعديل الملف الشخصي.
- إدارة المستخدمين والأقسام والتصنيفات والصلاحيات.
- إشعارات للمستخدمين وخرائط للبلاغات وإحصاءات وتقارير للأداء.
- تسجيل الأحداث الأمنية والعمليات الحساسة لأغراض التدقيق.

## متطلبات التشغيل

- PHP 8.2 أو أحدث، وComposer، وامتدادات PHP المطلوبة من Laravel، مع `pdo_sqlite` عند استخدام SQLite.
- Node.js بإصدار متوافق مع Vite 8، ومدير الحزم npm. يمكن استخدام Node.js 22.12 أو أحدث ضمن سلسلة 22.
- Flutter SDK متوافق مع متطلبات Dart واعتماديات التطبيق.
- Android SDK ومحاكي أو هاتف عند التشغيل على Android، وبيئة macOS مع Xcode عند التشغيل على iOS.
- اتصال بالإنترنت لتنزيل الاعتماديات وتحميل الخرائط والخطوط واستدعاء الخدمات الخارجية.

## التشغيل المحلي

الأوامر التالية مخصصة لإعداد نسخة تطوير محلية. تُنفّذ أوامر كل مكون من مجلده، وفي نافذة طرفية مستقلة عند تشغيل الخدمات معًا.

### 1. إعداد خادم Laravel

من جذر المشروع:

```powershell
cd municipality_system
composer install
```

عند الإعداد لأول مرة، انسخ `.env.example` إلى `.env`. في PowerShell:

```powershell
Copy-Item .env.example .env
php artisan key:generate
```

اضبط القيم التالية في `.env`:

```dotenv
APP_NAME="Baladiyati"
APP_URL=http://127.0.0.1:8000
DB_CONNECTION=sqlite
```

أنشئ ملف قاعدة البيانات إن لم يكن موجودًا، ثم أنشئ الجداول والبيانات الأولية ورابط الملفات المرفوعة:

```powershell
php -r "if (!file_exists('database/database.sqlite')) { touch('database/database.sqlite'); }"
php artisan migrate --seed
php artisan storage:link
php artisan serve --host=127.0.0.1 --port=8000
```

عنوان واجهات API المحلية: `http://127.0.0.1:8000/api`.

ينشئ `DatabaseSeeder` الأدوار والصلاحيات والأقسام والتصنيفات والحسابات التجريبية. إعادة تشغيله قد تعيد ضبط بيانات هذه الحسابات وصلاحيات الأدوار، لذا استخدمه مع قاعدة التطوير المخصصة للمشروع.

### 2. تشغيل لوحات التحكم

من جذر المشروع، في نافذة أخرى:

```powershell
cd baladity-Dashborads
npm install
npm run dev
```

افتح العنوان الذي يظهر في الطرفية؛ المنفذ المحدد في الإعدادات هو `5173`، وعادةً يكون العنوان `http://localhost:5173`.

عنوان API الافتراضي هو `http://127.0.0.1:8000/api`. لتغييره، أنشئ ملف `.env.local` داخل مجلد لوحة التحكم:

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8000/api
```

أعد تشغيل Vite بعد تغيير متغيرات البيئة.

### 3. تشغيل تطبيق Flutter

من جذر المشروع، في نافذة أخرى:

```powershell
cd baladity-mobileAPP
flutter pub get
flutter devices
```

اختر عنوان الخادم الذي يستطيع الجهاز الوصول إليه. مثال لمحاكي Android:

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000/api
```

| بيئة التشغيل | عنوان API |
|---|---|
| محاكي Android الافتراضي | `http://10.0.2.2:8000/api` |
| محاكي iOS على جهاز الخادم نفسه | `http://localhost:8000/api` |
| Android عبر USB مع تحويل المنفذ | `http://127.0.0.1:8000/api` |
| هاتف على الشبكة المحلية نفسها | `http://<LOCAL_IP>:8000/api` |

للعمل عبر USB، نفّذ `adb reverse tcp:8000 tcp:8000` ثم استخدم عنوان `127.0.0.1`. عنوان التطبيق الافتراضي هو `http://127.0.0.1:8000/api`، ويحتاج الهاتف إلى تحويل المنفذ للوصول إليه بهذه الطريقة.

للهاتف المتصل عبر Wi-Fi، شغّل Laravel بالأمر التالي واستخدم عنوان IP المحلي للحاسوب بدل `<LOCAL_IP>`، مع السماح بالاتصال على المنفذ `8000` في جدار الحماية:

```powershell
php artisan serve --host=0.0.0.0 --port=8000
```

اضبط `APP_URL` أيضًا على عنوان الخادم الذي يمكن للهاتف الوصول إليه، حتى تعمل روابط الصور المولّدة من الخادم، ثم نفّذ `php artisan config:clear` بعد تعديل الإعدادات.

## الحسابات التجريبية

بعد تنفيذ `php artisan migrate --seed` على قاعدة جديدة، تتوفر الحسابات التالية بكلمة مرور مشتركة هي `password`:

| الدور | البريد الإلكتروني |
|---|---|
| مدير النظام | `admin@baladiyati.test` |
| موظف الاستقبال | `reception@baladiyati.test` |
| مواطن تجريبي | `citizen@baladiyati.test` |
| حساب القسم | `department<ID>@baladiyati.test`، حيث `<ID>` معرّف القسم |

هذه الحسابات مخصصة للتجربة المحلية، ويجب تغيير كلمات مرورها أو استبدالها عند تجهيز بيئة نشر.

## إعداد الخدمات المساندة

### البريد الإلكتروني وOTP

الإعداد الافتراضي في `.env.example` هو `MAIL_MAILER=log`؛ تُكتب الرسائل في سجل Laravel بدل إرسالها إلى البريد. في الإعداد الافتراضي يمكن مراجعتها في `municipality_system/storage/logs/laravel.log`.

لإرسال رسائل OTP ورسائل حسابات الموظفين فعليًا، اضبط `MAIL_MAILER=smtp` وبيانات `MAIL_HOST` و`MAIL_PORT` و`MAIL_USERNAME` و`MAIL_PASSWORD` و`MAIL_FROM_ADDRESS` وفق مزوّد البريد.

### تصنيف صور البلاغات

أضف مفتاح الخدمة إلى ملف `.env` الخاص بالخادم:

```dotenv
GROQ_API_KEY=your_api_key
```

يمكن تخصيص النموذج ونقطة الاتصال باستخدام `GROQ_MODEL` و`GROQ_ENDPOINT` وفق إعدادات `config/services.php`.

عند غياب المفتاح أو تعذّر استدعاء الخدمة، يستخدم الكود مطابقة كلمات من اسم الملف ونوعه بوصفها آلية احتياطية؛ هذه الآلية لا تحلل محتوى الصورة بصريًا. يظل اختيار التصنيف يدويًا متاحًا.

### متابعة مهلة المعالجة

يشغّل Laravel المهمة `reports:escalate-sla` كل خمس دقائق عند تشغيل المجدول. للتطوير، افتح طرفية داخل `municipality_system` ونفّذ:

```powershell
php artisan schedule:work
```

يمكن تشغيل المتابعة مرة واحدة باستخدام:

```powershell
php artisan reports:escalate-sla
```

## التحقق والبناء

نفّذ الأوامر من مجلد المكون المقابل:

| المكون | الأمر | الغرض |
|---|---|---|
| Laravel | `php artisan test` | تشغيل اختبارات الخادم |
| Laravel | `php artisan test --filter=ReportWorkflowTest` | اختبارات دورة البلاغات ووظائف مرتبطة بها |
| Laravel | `php artisan route:list --path=api` | عرض مسارات API |
| لوحة التحكم | `npm run typecheck` | فحص أنواع TypeScript |
| لوحة التحكم | `npm run build` | فحص الأنواع وإنتاج ملفات البناء في `dist/` |
| لوحة التحكم | `npm run preview` | معاينة البناء محليًا |
| Flutter | `flutter analyze` | تحليل الكود |
| Flutter | `flutter test` | تشغيل اختبارات التطبيق الموجودة |
| Flutter | `flutter build apk --release` | بناء APK باستخدام إعدادات Android المتاحة |

اختبارات Laravel معدّة في `phpunit.xml` لاستخدام SQLite في الذاكرة. لا توجد حاليًا حزمة اختبارات مفعّلة للوحة التحكم عبر `npm test`؛ الأمر الموجود يعرض رسالة بعدم تعريف اختبارات.
